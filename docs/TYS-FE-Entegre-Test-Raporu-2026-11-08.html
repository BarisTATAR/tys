3. Entegrasyon sonucu (ne kanıtlandı?)

  • tys-fe ↔ tys bağlantısı çalışıyor: Login, oda, rezervasyon, misafir, cafe, SMS alıcıları, kurallar dosyası proxy üzerinden tutarlı.
  • FE koruma katmanı var, BE create katmanı zayıf: UI “en az bir oda”yı engelliyor; update BE de engelliyor; ama create çakışma/tarih kurallarını FE atlatılarak (proxy/API) kırılabiliyor.
  • Veri tutarlılığı: Proxy ile oluşturulan e2e-fe-proxy rezervasyonu UI Rezervasyonlar + Misafirler’de göründü.
  • Tenant riski FE’den de görünür: Proxy ile /room/by-company/2 sızıntısı tekrarlandı (FE bu endpoint’i normal menüde kullanmasa da API açık).

4. P0 aksiyon listesi

P0-1 · Create oda çakışması

  • FE proxy ile örtüşen create 200 döndü; UI müsait listesi yanıltıcı olabilir.
  • Update’teki availability kontrolünü createReservation’a taşıyın.

P0-2 · Create tarih doğrulama

  • checkOut > checkIn BE zorunlu kural olsun (400).
  • FE varsayılan checkout’u +1 gün yapın.

P0-3 · Tenant izolasyonu

  • /room/by-company/{id} JWT companyId ile eşleşmezse 403.
