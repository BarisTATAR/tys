01 · Ürün

TYS nedir?

Oteller, pansiyonlar ve benzeri tesisler için günlük operasyonu tek panelde toplayan çok kiracılı (multi-tenant) yönetim sistemi.

Çokluİşletme izolasyonu
BoardTarihli oda tahtası
YaşamRezervasyon döngüsü
OnayKurallar + SMS linki

Operasyon

Ana Ekran, rezervasyon, misafir, oda, checkout ve ödemeler.

Tesis yönetimi

İşletme kaydı, oda kotası, cafe menü, işletme kuralları.

Dış dünya

VatanSMS, KBS (Jandarma) SOAP istemcisi, Excel misafir import.

02 · Aktörler

Üç erişim düzlemi

ADMIN ROLE_ADMIN

  • İşletme ekleme / listeleme
  • Oda ekleme ve güncelleme
  • Oda kotası (totalRoomNumber)
  • JWT: adminId

COMPANY ROLE_COMPANY

  • Günlük tesis operasyonu
  • Rezervasyon, misafir, ödeme, cafe
  • SMS / kurallar gönderimi
  • JWT: companyId ile scoped

Public JWT yok

  • Kurallar görüntüleme
  • Token ile onay sayfası
  • /kurallar-onay/:token
  • Login / şirket oluşturma

Not: FE’deki “Yönetim Paneli” /company/admin_login kullanır ve ADMIN değil, COMPANY JWT üretir.

03 · Modüller

Operasyon haritası

Ana Ekran

  • Tarihli oda board
  • Durum renkleri
  • Sağ tık → güncelle
  • Çoklu oda düzenleme

Rezervasyon

  • Yeni kayıt / liste
  • Oda + misafir sync
  • Kahvaltılı / odalı
  • Yetişkin–çocuk–bebek

Misafir

  • CRUD + iletişim kişisi
  • Geçmiş / filtre
  • Excel import
  • TC tekilliği

Ödeme & Cafe

  • Nakit / kart / banka
  • Peşin & ara ödeme
  • Menü + kalemler
  • Checkout borcuna dahil

SMS & Kurallar

Word (.docx) yükleme, onay linki SMS, public onay sayfası.

KBS

Jandarma SOAP: check-in/out, yabancı misafir, parametre listesi.

Rapor / Analiz

FE iskelet sayfalar — henüz üretim işlevi yok.

03 · Rezervasyon

Durum yaşam döngüsü

RESERVATION_MADE → GUEST_INFORMATION_ENTERED → CHECK_IN_DONE → CHECK_OUT_DONE
  • Bir rezervasyon birden fazla odaya bağlanabilir.
  • Güncellemede odalar ve misafirler senkronize edilir (id varsa update, yoksa create).
  • Checkout sonrası oda board’da boş görünür; doluluk hesabına girmez.
  • Liste filtresi: çıkış tarihi bugünden önce olanlar ana listede yoktur.

Kritik kapı

Check-out, ödeme + cafe toplamı kapanmadan engellenir.

“Tüm borçlar kapatılmadan Check-out yapılamaz…”

04 · Güvenlik

Kimlik ve erişim modeli

JWT (stateless)

  • Bearer token · oturum sunucuda tutulmaz
  • Süre: 30 dakika
  • Claim: role + companyId / adminId
  • Authority: ROLE_COMPANY / ROLE_ADMIN

Path politikası

  • permitAll login, create, /public/**
  • authenticated reservation, room, guest, payment, cafe, kbs…
  • Path bazlı hasRole yok — scoping servis/controller’da
  • CSRF kapalı · CORS localhost odaklı

Şirket kapsamı

Çoğu operasyon JWT companyId ile filtrelenir. Cafe menü/kalemlerde sahiplik kontrolü → 403.

Public kurallar

/public/rules/{token} görüntüle · .../approve onayla. Misafir paneli JWT’siz açılır.

05 · İş kuralları

Zorunlu kısıtlar

Oda & rezervasyon

  • En az 1 oda zorunlu
  • Çıkış > giriş; geçerli tarihler şart
  • Çakışan rezervasyon → müsait değil
  • Müsait liste: excludeReservationId ile kendi odaları korunur
  • FE kapasite: kişi ≤ odaların toplam kapasitesi

Tesis & veri

  • Oda sayısı ≤ işletme kotası (totalRoomNumber)
  • Kota, kayıtlı oda sayısının altına inemez
  • Kullanıcı adı ve TSS kodu tekil
  • Excel/DB TC tekilliği
  • Kurallar SMS: önce .docx yüklenmeli
“Oda X seçilen tarihlerde müsait değil (başka rezervasyon var).” — doluluk native sorgu + board filtresi ile çift doğrulanır.

07 · Sınırlar

Bilinen kısıtlar

Güvenlik & yetki

  • Path’te rol ayrımı zayıf — authenticated yeterli
  • Bazı liste/get uçlarında sahiplik her yerde yok
  • Parolalar düz metin karşılaştırma
  • SMS API anahtarları kaynakta

Ürün olgunluğu

  • KBS FE placeholder; check-in KBS/SMS çağrıları kapalı
  • Rapor / Değerlendirme Analizi iskelet
  • Kapasite ağırlıkla FE doğrulaması
  • Create tarafı update kadar sıkı değil

Operasyonel

JWT 30 dk · CORS production domain’leri dar · WSDL üretimi ağ/SSL’e bağımlı.

İsimlendirme tuzağı

admin_login (şirket) ≠ ROLE_ADMIN. Sunum ve eğitimde net ayrılmalı.

08 · Özet

Karar notları

Güçlü yan

Board + çoklu oda + checkout borç kuralı + kurallar SMS onayı ile sahada kullanılabilir operasyon çekirdeği.

Yetki özeti

ADMIN kurulum, COMPANY günlük iş, Public yalnızca token’lı kurallar onayı.

Öncelikli iyileştirme

Role hardening, parola hash, KBS SSL/FE, raporlar, create doğrulamasının BE’ye taşınması.
